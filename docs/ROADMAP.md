# 路线图（ROADMAP）

## 阶段 1 · 实测精选与教程（第 1–2 周）

**做什么**：按 [四关实测法](METHODOLOGY.md) 完成首批插件实测；发布三篇原创中文指南；报告格式与工具链定型。

**为什么是现在**：生态 800+ 插件、收录≠背书、无实测数据。做第一个"只发测试结论"的编辑位，建立标准。

**验收标准**：
- [x] 36 份实测报告（26 通过 + 10 失败已记录，覆盖 UI/工具/会话/记忆/计费/数据等类别）
- [x] 三篇指南（双语）：上手 / 写插件 / 避坑 + FAQ
- [x] `tools/scan.mjs` 快检工具开源可复现
- [x] 被第三方目录/社区提及（社区目录 [awesome-dsh-plugin](https://github.com/beancookie/awesome-dsh-plugin) 收录 dsh-lab）
- [ ] 被至少一个第三方目录或文章引用

## 阶段 2 · 兼容性矩阵（第 3–4 周）

**做什么**：DSH 每发一个新版本，CI 自动对全部被测插件重跑"安装+冒烟"两关，产出公开矩阵：

```
插件 \ DSH 版本      rc.6   rc.7   rc.8   ...
dsh-global-rules      ✅     ⏳     ⏳
dsh-mermaid           ✅     ⏳     ⏳
```

**为什么是前瞻的**：DSH 主线 rc 版本更新频繁，839 个插件即将进入批量坏掉的"漂移期"。今天没有人做这个矩阵；漂移期到来时，本仓库是唯一权威数据源——官方、插件作者、用户都会引用。这也是从"内容仓库"升级为"基础设施"的一步。

**验收标准**：
- [ ] GitHub Actions 每日自动重测 + 矩阵页
- [ ] 覆盖 top 50 高 star 插件
- [ ] 兼容状态徽章可供插件作者挂在 README

## 阶段 3 · 同类插件竞技场（第 5 周起）

**做什么**：对同类插件（例如 30 个余额显示面板、15 个会话导航）用同一组真实 headless 任务两两对比，发布赛报：谁的数据准、谁不崩溃、谁兼容好。

**为什么是前瞻的**：插件同质化已经失控（同功能 30 个实现）。用户需要的不是第 31 个推荐列表，而是"谁真的赢"。竞技场方法论成熟后可以覆盖整个生态，成为默认的裁决标准。

**验收标准**：
- [ ] 首个赛报（至少一个品类、5 个选手）
- [ ] 比赛任务集、评分口径、原始日志全部公开
- [ ] 赛报被至少一个插件作者引用或改进

---

**原则**：阶段可以并行，但顺序不颠倒——没有阶段 1 的编辑信任，阶段 2/3 的数据没人看；没有阶段 2 的基础设施，阶段 3 的结论无法持续。
